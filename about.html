ABOUT THIS POC

Browser port: the runway.

The environment is playable in the browser. That clears the way for the main experiment: putting a trained reinforcement-learning policy at the controls.

Current milestone · environment online

Next milestone · load a trained policy, connect its actions to the lander, and evaluate its episodes.

01 / WHY THE BROWSER

Make the experiment easy to try.

Pyodide runs Python in the browser, so the same environment logic can run on a static page. The goal is to make policy inference and landings visible without needing a game server.

02 / THE PHYSICS

Python all the way down.

PyPyBox2D supplies pure-Python rigid-body physics. A small local Gymnasium-compatible shim provides the environment and spaces interface used by LunarLander, without installing the full Gymnasium dependency tree.

03 / THE POLICY LOOP

Observation in. Action out.

The environment emits its eight-value observation. A trained policy will choose one of four discrete actions—coast, rotate left, fire the main engine, or rotate right—and the resulting flight can be scored episode by episode.

OBSERVATION→POLICY→ACTION→LANDER

04 / FIDELITY NOTES

A practical browser POC.

This implementation follows the classic LunarLander-v2 observation and reward structure, with PyPyBox2D’s older Box2D 2.1-era solver. It is not bit-for-bit identical to Gymnasium’s native Box2D 2.3 environment. Pyodide handles Python and NumPy; JavaScript draws the canvas and forwards keyboard input.

Physics engine: PyPyBox2D by Ken Lauer, from the 2.1-r331 PyPI source release. Distributed under the zlib license; the license notice is included in the wheel.
