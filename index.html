          ABOUT / CREDITS THE CABINET

          LUNAR LANDER — TOURNAMENT EDITION

          Who can stick the landing?

          Four pilots share this pad — and you can be one of them. Fly solo, drop into a 1v1 or 2v2 best-of-three, or run the four-pilot Cup. Same sky, same hazards, one question: who sticks the landing?

          Every pilot flies the identical course and the identical hazard timeline

          Same seed, same step, same sky. When a hazard fires, it fires for every pilot at the same physics step — so a match is won on skill, not luck.

          From a course project to a cabinet

          This cabinet began with the Hugging Face Deep RL Course (Unit 1 hands-on), which trains a PPO pilot on LunarLander-v2. That checkpoint — seekdepth/ppo-LunarLander-v2 — became the default pilot, and this Tournament Edition plays it live in your browser alongside four more pilots imported from other builders.

          01 / HOW TO USE IT

          Four ways to fly.

          Single Player is the training corner: fly it yourself, let the AI fly solo, or grab an Autopilot + Override stick. Tournament runs Versus (1v1), Doubles (2v2), or the four-pilot Cup. Arm hazards per match or per round — each has graded intensity — and every pilot flies the exact same sky.

          02 / THE PILOTS

          Eight readings in. One move out.

          Every pilot reads the same eight cockpit readings and picks one move: coast, tilt left, fire the main engine, or tilt right. Third-party DQN and PPO checkpoints are converted to the same observation[8] → logits[4] contract with parity validation.

          READINGS→PILOT→MOVE

          03 / TOOLING

          Python in the browser.

          The environment and physics run in Python through Pyodide 0.23.4. PyPyBox2D supplies the pure-Python rigid-body solver (Box2D 2.1-era) behind a small Gymnasium-compatible shim. JavaScript draws the canvas and runs inference with ONNX Runtime Web 1.19.2 on its WebAssembly CPU backend.

          04 / MODEL PIPELINE

          Era-pinned exporters.

          Docker images pinned to the era of each checkpoint (python:3.7 + torch==1.13; python:3.8 + tensorflow==2.12 + tf2onnx) export third-party weights to the shared observation[8] → logits[4] ONNX contract, checked against the original policy before they fly here.

          Sandbox physics · scores are this cabinet’s, not the official leaderboard.

          How the cabinet is built

          The port follows the classic LunarLander-v2 observation and reward structure but is not bit-for-bit identical to the native Box2D environment: it uses PyPyBox2D’s older Box2D 2.1-era solver plus a settled-contact landing completion rule.

          Reference material: the LunarLander-v2 environment, the adapted LunarLander source, Stable-Baselines3 PPO, Pyodide 0.23-series deployment, ONNX Runtime Web, and PyPyBox2D 2.1-r331 by Ken Lauer.

          The cabinet source is at github.com/jpeckenpaugh/rl-livive-net.
